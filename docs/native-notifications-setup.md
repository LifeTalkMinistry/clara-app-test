# CLARA native notifications setup

CLARA uses a universal notification bridge:

- Supported web browser or installed PWA: Web Push through the existing service worker.
- Android installed app through Capacitor: native push through Capacitor Push Notifications and Firebase Cloud Messaging.
- iOS installed app through Capacitor: native push scaffold through Capacitor Push Notifications.
- Unsupported browser or WebView: in-app notifications remain available.

This system intentionally keeps two tests separate:

- **Local test notification** = generated by this device through browser/local notification APIs.
- **Real push test notification** = sent from Supabase/Firebase to this phone through FCM.

A local notification is useful for checking phone/browser permission and tap routing, but it is not proof that outside-app push works.

## 1. Install and sync Capacitor notification plugins

```bash
npm install @capacitor/push-notifications @capacitor/local-notifications
npx cap sync
```

Run `npx cap sync android` before opening Android Studio after dependency changes.

## 2. Firebase Console setup for Android

1. Create or open the Firebase project for CLARA.
2. Add an Android app using the CLARA package id:

   ```text
   com.clara.lifeos.app
   ```

3. Download `google-services.json`.
4. Place it at:

   ```text
   android/app/google-services.json
   ```

Do not commit a production `google-services.json` unless the project policy explicitly allows it. Use a placeholder or keep it in local/CI secrets when possible.

If Android registration fails, verify that this file exists in the Android app module and that the package id inside Firebase matches `com.clara.lifeos.app`.

## 3. Android native requirements

The Android app must include:

- Android 13+ permission:

  ```xml
  android.permission.POST_NOTIFICATIONS
  ```

- Notification channel id:

  ```text
  clara_reminders
  ```

- Channel name:

  ```text
  CLARA Reminders
  ```

- Importance:

  ```text
  High
  ```

- Description:

  ```text
  Money reminders and important CLARA updates.
  ```

The app creates the channel in `MainActivity.java` and adds the permission in `AndroidManifest.xml`.

## 4. Supabase schema

Run the universal notification device migration:

```sql
supabase/universal_notification_devices.sql
```

This creates `public.user_notification_devices` for native FCM/APNs tokens and mirrored web-push subscriptions. The old `public.user_push_subscriptions` table remains for backward compatibility.

To verify a saved Android FCM token:

```sql
select
  id,
  user_id,
  channel,
  platform,
  token is not null as has_token,
  is_active,
  last_seen_at
from public.user_notification_devices
where channel = 'fcm'
  and platform = 'android'
order by last_seen_at desc
limit 20;
```

Expected active Android row after enabling phone notifications:

```text
channel = fcm
platform = android
token is not empty
is_active = true
```

## 5. Supabase edge function secrets

Web Push still needs:

```bash
supabase secrets set VAPID_PUBLIC_KEY=...
supabase secrets set VAPID_PRIVATE_KEY=...
supabase secrets set VAPID_SUBJECT="mailto:support@clara.app"
```

Android FCM needs Firebase service account secrets:

```bash
supabase secrets set FIREBASE_PROJECT_ID=...
supabase secrets set FIREBASE_CLIENT_EMAIL=...
supabase secrets set FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
```

Keep the private key quoted so newline escapes are preserved.

The scheduled/internal caller still uses:

```bash
supabase secrets set TASK_REMINDER_INTERNAL_SECRET=...
```

The manual real push test may be called by the signed-in user only when `event_type` is `manual_push_test` and `user_id` matches that Supabase session. Do not expose `SUPABASE_SERVICE_ROLE_KEY` or `TASK_REMINDER_INTERNAL_SECRET` in the app.

## 6. Frontend cloud env required for real push diagnostics

The Android installed app must be built with Supabase cloud env vars when using the real push diagnostic:

```bash
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

Without these, the app should show:

```text
Supabase cloud is not configured. Add VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY before testing real push.
```

## 7. Build and open Android

```bash
npm install
npx cap sync android
npm run build:android
npx cap open android
```

In Android Studio, build and install the app on a real device. Push notification behavior should be tested on a physical device, not only an emulator.

## 8. How to test real Android push

On a physical Android device with the installed Capacitor app:

1. Open CLARA.
2. Go to Settings → Notifications.
3. Open Advanced task reminder schedule.
4. Tap **Enable phone notifications**.
5. Android should request notification permission.
6. Confirm an active `public.user_notification_devices` row exists with:
   - `user_id = current signed-in Supabase user`
   - `channel = fcm`
   - `platform = android`
   - `token` is not empty
   - `is_active = true`
7. Tap **Send real push test**.
8. The app calls `send-task-reminders` with this payload shape:

   ```json
   {
     "user_id": "currentUser.id",
     "title": "CLARA push test",
     "body": "This was sent from Supabase/Firebase to your phone.",
     "url": "#/dashboard",
     "dedupe_key": "manual_push_test:<timestamp>",
     "event_type": "manual_push_test"
   }
   ```

9. A successful result should include `nativeSent: 1` or `sent: 1`.
10. Confirm the notification appears outside the app in the phone notification tray or lock screen.
11. Tap the notification and confirm CLARA opens to the payload route.

## 9. Local device test

Use **Send local device test** only to verify local notification permission and local tap routing.

Expected local copy:

```text
Local test notification = generated by this device.
```

This must not be described as real push and must not be treated as proof that Supabase/Firebase/FCM works.

## 10. Testing checklist

### Desktop browser

- Settings → Notifications shows browser/web app wording.
- Enable device notifications uses Web Push when VAPID is configured.
- Local/browser test notification works.
- Existing service worker still handles notification taps.

### Unsupported browser or WebView

- Settings → Notifications says browser notifications are unavailable.
- The app does not crash.
- In-app notifications still work.
- Notification category toggles remain usable.
- Real native FCM test says Android installed app is required.

### Android Capacitor installed app

- Settings → Notifications does not say “This browser cannot receive device notifications.”
- It shows phone/native notification copy.
- Enable phone notifications requests Android permission.
- A token is saved to `user_notification_devices` with channel `fcm` and platform `android`.
- **Send local device test** creates only a local device notification.
- **Send real push test** calls Supabase/Firebase and returns `nativeSent: 1` or `sent: 1` when successful.
- Notification taps open the CLARA route from the payload data.
- `send-task-reminders` can send to the FCM token after Firebase secrets are configured.

### Supabase

- `user_notification_devices` migration runs cleanly.
- Existing `user_push_subscriptions` rows still work as fallback.
- Invalid FCM or Web Push targets are deactivated without failing the whole function.
- Manual push tests fail loudly if Firebase secrets are missing, the FCM token is missing, or the device table cannot be queried.

## 11. Common failure reasons

- **Permission denied:** Android notification permission is blocked. Enable CLARA notifications in device settings.
- **No FCM token:** `google-services.json` is missing, package id mismatches Firebase, Play services is unavailable, or Capacitor registration failed.
- **Supabase cloud not configured:** `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are missing from the app build.
- **Missing device table:** `public.user_notification_devices` migration has not been applied.
- **Firebase secrets missing:** `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, or `FIREBASE_PRIVATE_KEY` is missing from Supabase Edge Function secrets.
- **Unauthorized manual push:** the payload `user_id` does not match the signed-in Supabase session user.
- **Local-only beta session:** the local app session cannot prove Supabase/Firebase delivery. Real push diagnostic requires a Supabase cloud session.
- **FCM invalid/unregistered:** the token belongs to an old install or Firebase project; reinstall or refresh the token, then retry.
