# CLARA native notifications setup

CLARA uses its own backend for notification registration, preferences, and delivery coordination.

## Delivery paths

- Supported web browser or installed PWA: Web Push through the CLARA service worker and backend subscription endpoints.
- Android installed app through Capacitor: native push through Capacitor Push Notifications and Firebase Cloud Messaging.
- iOS installed app through Capacitor: native push through Capacitor Push Notifications and APNs-compatible device registration.
- Unsupported browser or WebView: in-app notifications remain available.

A **local device test** is generated by the current device and verifies local permission/tap routing. A **real push test** is delivered through the CLARA Backend and the platform push service. These are separate tests.

## Backend endpoints

The app uses the CLARA Backend for notification ownership:

- `POST /api/push/subscriptions` — register a web push subscription.
- `GET /api/push/preferences` — read push preferences.
- `PUT /api/push/preferences` — update push preferences.
- `POST /api/push/send-test` — request a real push test.
- `POST /api/notifications/devices` — register a native device token.
- `DELETE /api/notifications/devices/:token` — unregister a native device token.

The frontend backend URL is configured with `VITE_CLARA_API_URL` when an override is required.

## Android setup

Install and sync the notification plugins:

```bash
npm install @capacitor/push-notifications @capacitor/local-notifications
npx cap sync android
```

Configure Firebase for package id:

```text
com.clara.lifeos.app
```

Place the Android Firebase configuration at:

```text
android/app/google-services.json
```

Android 13+ requires `android.permission.POST_NOTIFICATIONS`.

CLARA uses the notification channel:

```text
id: clara_reminders
name: CLARA Reminders
importance: High
```

## Build and test

```bash
npm install
npx cap sync android
npm run build:android
npx cap open android
```

Test native push on a physical Android device.

1. Sign in to CLARA.
2. Open Settings → Notifications.
3. Enable phone notifications.
4. Accept the Android notification permission prompt.
5. Confirm device registration succeeds through the CLARA Backend.
6. Send a real push test.
7. Confirm the notification appears outside the app.
8. Tap it and confirm CLARA opens the intended route.

Use the local-device test only for local permission and tap-routing checks; it does not prove remote push delivery.

## Common failure reasons

- Notification permission is denied in device settings.
- Firebase configuration is missing or the Android package id does not match.
- Google Play services cannot register the device.
- The CLARA Backend is unavailable or the authenticated session is invalid.
- The native token belongs to an old installation and must be refreshed.
- Push-provider credentials required by the CLARA Backend are missing from the backend environment.

Private push credentials belong on the CLARA Backend. Do not expose them in frontend environment variables or commit them to the app repository.
